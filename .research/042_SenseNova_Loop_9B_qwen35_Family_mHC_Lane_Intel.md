## TL;DR

SenseNova-Loop-9B (SenseTime, 2026-11-17) is the **third public looped-transformer checkpoint family** (after Dory 1.0-4B and Inkling 2 Mini) and the **first built on HF's Qwen3.5 base classes** — the same hybrid DeltaNet/attention family as our league model Bonsai-2-27B (`class SenseNovaLoopConfig(Qwen3_5Config)`, 3 linear + 1 full attention per 4-layer group = our `qwen35.full_attention_interval=4` shape). That makes it the nearest-to-home looped checkpoint yet: a serving port would be a **delta on a forward we already ship** (loop plan + mHC + per-visit KV), not a new architecture the way Dory was. The serving semantics worth recording: a **fixed-count loop plan** (`counts != [count]` refused — NOT varloop, so 1221's elastic-k halter seam does NOT map), **per-visit KV slots** ("Repeated visits share weights, but each visit has its own cache slot" — 14 full-attention KV slots per token by our arithmetic), an **FP32-forced log-space Sinkhorn mHC router** that may not cross a loop phase boundary, and a **qwen3.5-nextn MTP** draft head (the layout our qwen38 loader already reads via `nextn_predict_layers`). Self-reported: ~27B-class agentic/data quality at 9B (14.6B inference-equivalent), 512K ctx, ~15 GiB at 256K with 4-bit weights + 8-bit KV. For us: (1) lane intel into 1221 — the T2-proven **LastLoop KV policy is the first experiment a port would run**, since SenseNova hardwires per-visit KV that our Dory work showed is memory-dominated; (2) the decision-serving seat stays DEFERRED (R038 §3.4 framework; SenseNova is weaker-positioned than Inkling for decision suites — no board standing, weaknesses unnamed); (3) teacher candidacy filed as rethink 068 with the lg4b-lesson prior stated honestly; (4) the specdec lanes stay PAUSED unchanged; (5) the perf league never moves — looping is a quality-per-parameter lever that COSTS decode tok/s (~1.75× layer executions/token), never a speed lever.

## 1. The model, from the code (not the README)

**Base.** `SenseNovaLoopConfig(Qwen3_5Config)` with `model_type = "sensenova_loop"`; the text model subclasses `hf.Qwen3_5TextModel`, layers `hf.Qwen3_5DecoderLayer`, the conditional-generation head `hf.Qwen3_5ForConditionalGeneration`. 32 physical layers, hidden 4096, FFN 12288, GQA 16/4 heads; layer types `{"full_attention", "linear_attention"}` with the qwen3.5 interval-4 pattern (README: three linear + one full per group). Linear attention carries qwen3.5 DeltaNet-style conv + recurrent state (`_VisitCache.update_conv_state`/`update_recurrent_state` — the same state surfaces our Bonsai forward serves). Multimodal via 4D mrope positions (`position_ids.view(1, 1, -1).expand(4, …)`, text at index 0, vision at 1:) — text-only serving ignores the vision dims, exactly the qwen3.5-VL posture.

**Loop execution.** `execution_plan(config)` returns the physical-index visit order: `tuple(range(start)) + tuple(range(start, end)) * count + tuple(range(end, num_layers))` — for the release, layers [4,28) run twice → 56 executions/token from 32 distinct layers. Validation laws, all fail-loud at load (worth transcribing as hygiene faces):
- `raise ValueError("Only fixed-count Loop checkpoints are supported")` — `loop.get("counts") != [count]` refuses; **no varloop checkpoint class exists**, so the elastic-k dial is structurally absent (vs Inkling's `TML-d24-varloop` and 1221's cache-at-k).
- At least one full-attention layer is required "for sequence-length tracking".
- **mHC phase law**: `raise ValueError("MHC cannot cross a Loop phase boundary")` — the mHC span must sit entirely inside one of (pre-loop, looped, post-loop).

**Per-visit KV (the load-bearing serving fact).** The cache is a `DynamicCache` configured to the EXECUTION plan (`past_key_values._loop_execution_plan = self._loop_plan`), with the comment: `# Repeated visits share weights, but each visit has its own cache slot.` — `_VisitCache(past_key_values, physical_index, execution_index)` maps every visit to its own slot; a populated cache from a different execution plan refuses ("A populated cache from another execution plan cannot be reused"). Arithmetic (ours, labeled): at interval 4 the 32 layers hold 8 full-attention layers → visits = 1 (pre-loop) + 6×2 (looped) + 1 (post) = **14 full-attention KV slots per token**, plus 42 per-visit DeltaNet recurrent/conv states (3 pre-loop + 18 looped × 2 passes + 3 post-loop; check 14 + 42 = 56 visits ✓). Their 8-bit-KV deployment table (~15 GiB at 256K with ~4.9 GB of 4-bit weights) is consistent with that shape. Contrast: our Dory T2 proved **LastLoop KV is k-independent in memory and argmax-stable over the tested horizon** (Bench 1232: per-loop 1,572,864 vs last-loop 589,824 elements at k=4, 4× recurrent reduction, argmax 16/16) — SenseNova hardwires the expensive PerLoop posture and ships no policy choice. **A port's first experiment is DoryKvCachePolicy::LastLoop over the 14 visits.**

**mHC (two-stream).** The router is FP32-by-construction, twice enforced — a `_apply` hook that keeps parameters FP32 under a BF16 cast, plus a runtime guard: `raise RuntimeError("mHC routers require FP32 parameters; configure FSDP per-module precision")`. Forward (autocast disabled): RMSNorm over the flattened streams → linear → `pre = sigmoid(logits[:s])` (read gates), `post = 2·sigmoid(logits[s:2s])` (write gates, ≤2.0), and the mix matrix from `sinkhorn(logits[2s:].unflatten(…), iterations)` (identity-expand under `fixed_identity`). The Sinkhorn itself is log-space, entropy-free, iterations from config (20 per README):

```python
def sinkhorn(logits, iterations):
    """Normalize routing logits across rows and columns in log space."""
    logits = logits.float()
    for _ in range(iterations):
        logits = logits - torch.logsumexp(logits, dim=-1, keepdim=True)
        logits = logits - torch.logsumexp(logits, dim=-2, keepdim=True)
    return logits.exp()
```

Merge: `mixed = mix @ residual` (the doubly-stochastic matrix mixes the two streams), `+ post ⊗ branch` (the branch output gated into every stream); `enter` expands one stream into N identical copies at the mHC span start, `leave` means over streams at the span end. Bias init pins near-uniform transport (2 streams: logit(0.25/0.75); 4: identity×log(14)), i.e. the training prior starts at ~identity mixing. All of this is the mHC paper's mechanism (2512.24880) applied inside a looped span — the two-stream instance is SenseNova's configuration choice, not a new primitive.

**MTP + specdec transactions.** `models/mtp.py`: "Checkpoint-compatible Qwen3.5 MTP predictor for the Loop backbone" — single full-attention layer, shared embeddings/output projection, fc over concat(pre-norm(embed), pre-norm(hidden)); "The parameter layout follows the released `mtp.*` checkpoint tensors and vLLM's Qwen3_5MultiTokenPredictor (Apache-2.0)" — the same nextn shape our qwen38 loaders already probe (`nextn_predict_layers` in `qwen38_dense_cudarc.rs`). `speculative_cache.py` is the hybrid-attention specdec transaction: `CacheCheckpoint` "saves recurrent state without copying the growing full-attention KV cache" — append-only KV is cropped on rollback, while conv/recurrent states (mutated in place) are CLONED at checkpoint and copied back before replay: "Rollback precedes replay of accepted tokens"; `crop_draft_cache` handles teacher-forced catch-up. Face-grade beside our GDN state-snapshot faces (kernel_opt gpu_152's family), but a clean statement of the hybrid verify/rollback law.

**Loop scaling (self-reported, their cells).** On the loop-trained 9B: loop 1 baseline → best at 3 loops for two tasks (+6.42%/+16.93% relative), 4 loops for two others (+8.10%/+8.55%); 2→4 loops buys +1.04 pp LiveCodeBench-V6 / +1.35 pp AIDABench-DV; deeper loops "open for further study"; dynamic per-input loop counts named as future work. This matches 2610.40325's findings (middle-block looping pays when training FLOPs are the constraint — their [4,28) middle block is exactly that cell; gains saturate/reverse/unstable; loop-specific low-rank adapters help deeper; decode slowdown ∝ loops; PLT parallel-looping quality-fragile in the original formulation). Release ships 2 loops as the efficiency default. **The serving dial reading:** loop count is a quality/latency dial ONLY on a loop-trained checkpoint (train/inference depth must match — the same law 038 recorded for Inkling); on OUR decision-serving surface the dial would be an ESC-adjacent compute axis (escalate = more loops) for a looped think leg, parked with the seat question.
