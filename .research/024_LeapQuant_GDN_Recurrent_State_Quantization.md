## TL;DR

LeapQuant quantizes the **recurrent state** of GDN/KDA linear-attention layers to 8 bits, training-free, at near-FP32 accuracy (Table 1: avg 84.4 vs FP32's 84.0 across 12 model–task pairs — while per-step BF16 state quantization scores **72.5** and per-step INT8 47.7), via three training-free components: (1) **per-window quantization** — quantize the state once per p=16-token window, hold the low-bit boundary state fixed, buffer the window's records `(αᵢ, kᵢ, uᵢ)` in FP16, compute in-window outputs from fixed state + records (the chunkwise unroll, Eq. 4/10); (2) **Compensator Tokens** — r=4 rank-one outer products (power-iteration fit) capturing the state's dominant outliers in FP16, shaped exactly like real-token updates so they ride the same buffer path ("the Compensator Tokens are handled exactly like R extra buffer entries with weight 1" — `make_gdn_step` docstring @ pin); (3) **residual smoothing** — per-key-row scales c = √(mean |row|), recomputed at every window boundary (outliers 176× median → 47× after CTs → 5.3× after smoothing, Fig. 6). Kernel 2.05–4.25× vs FP32 FLA (batch-scaled), decode 1.22–1.57×, e2e 1.47–1.57× (one cell 2.98×), state stored at 1.19 B/elem (3.4× traffic cut), e2e memory −41–56% under prefix caching.

**Distilled for riir-infer (public serving substrate):** all three components are deterministic runtime math — window unrolling, a power-iteration rank-1 fit, per-row scale migration. Zero training, zero calibration data. Our hybrid lane quantizes the **KV half** (`ternary_kvq.rs`, Issue 919 T3: "The DeltaNet layers carry no KV by construction (a fixed recurrent state, not a per-token cache)") and defaults every GDN state to f32 — the one state-quant arm in the stack is the opt-in per-step f16 `RIIR_GDN_STATE_HALF` (promotion declined on sequence forking, cousin #2 below); **no windowed / sub-16-bit state lane exists**. This paper is the published method for exactly that missing lane, on our exact model families (Qwen3.5/3.8 GDN, GLM-5.3-Flash KDA, Kimi-Linear KDA).

## 1. Paper core findings (verified against the fetched full text, v2)

1. **Error accumulation is the failure mode, and frequency is the lever.** Per-step re-quantization carries each rounding error into every subsequent update (their Eq. 9: `Eₜ = Diag(αₜ)Eₜ₋₁ − wₜ(Eₜ₋₁ᵀbₜ)ᵀ + εₜ` — the same decay + delta-erase recurrence Research 538 used to explain GDN's quantization *survival*). Per-step error grows steadily over 64K decoded tokens even at BF16; quantizing once per 16-token window cuts the 64K error **100× for BF16, 39× for INT8** (Fig. 3). Stochastic rounding does not rescue per-step (−3× at BF16, INT8 diverges).
2. **Outliers are row/column-concentrated and few.** A few singular components carry most of the state's energy (top-4 ≈ saturation, Fig. 5); magnitude outliers reach 176× the median. Removing r=4 rank-one components + smoothing leaves a residual that quantizes at ~FP32 fidelity.
3. **The buffer readout never forms the state** (their Eq. 10): `Sᵢᵀx = Ŝ₀ᵀΓ₁:ᵢx + Σⱼ uⱼ(kⱼᵀΓⱼ₊₁:ᵢx)` — O(dk·dv) for the fixed-state term, O(dk+dv) per buffered record, cumulative decays maintained incrementally. The decode kernel reads the low-bit state once and never materializes a dense intermediate.
4. **Generality table (their Table 4):** the record form `(α, w, u)` covers Linear Attention, RetNet, Mamba2, GLA/RWKV6/HGRN2, DeltaNet, GDN, KDA, DeltaProduct; RWKV7's separate erase direction splits into two records per token. Buffer sizes pinned per family (GDN: 1+dk+dv per token; KDA: 2dk+dv).
5. **Serving-side wins beyond decode:** state checkpoints under prefix caching (one per ~1K cached tokens, Marconi-style) shrink 3.4× → e2e memory −41–56% → up to 1.4× more concurrent requests; the gain grows with batch (state traffic share grows) and stays 1.20–1.25× at 128K context on sparse-attention hybrids (Fig. 11).
6. **Ablation honesty (Table 2):** per-window alone at INT8: AIME 7.1→82.4; +CTs → 86.6; +smoothing → 87.9 (=FP32). Kernel 2.43→2.52× (CT overhead mostly hidden under the state read; r=16 exposes it to 0.74× — slower than FP32). p=16 is the measured optimum (p=32: no accuracy gain, kernel 2.52→2.20×).
7. **Caveats we carry:** all speedups are CUDA (B200 / RTX PRO 6000 / RTX 5090, TileLang persistent warp-specialized kernels) — **no Metal numbers exist**; accuracy is downstream-benchmark-level (no perplexity tables in the main text); vLLM-only integration (plugin monkey-patches `fused_sigmoid_gating_delta_rule_update` + `_forward_core`; prefill slots take an fp32 round trip around vLLM's own prefill kernel).

### Closest cousins (checked by formula read, not name match)

1. **`src/deltanet/ternary_kvq.rs` (Issue 919 T3)** — quantizes KV **rows at store time** for the attention layers; the recurrent state is never a store target. *Signal diff:* per-token append-only rows vs a fixed-size matrix overwritten every token; store-time one-shot quant vs a **recurrent** scheme where the quantized value feeds the next update (LeapQuant's entire §3.2 exists because naive store-time-on-write is impossible for a state that is re-read and re-written every step). Complementary, not covering.
2. **`RIIR_GDN_STATE_HALF` (riir-ai Plan 611 / Bench 954, opt-in, demoted posture)** — the SHIPPED per-step f16/bf16 state lane: banked +0.44% decode, G4 144→72 MiB resident — and NO promotion, because the measured blocker is **sequence-level forking at deployment lengths** (0/6 sequences identical at 512-token greedy walks; greedy-32 17/18 is the flat aggregate). *Signal diff:* per-step re-quantization of the state is exactly the error-accumulation mode §1.1 shows growing unboundedly even at BF16 — LeapQuant's windowed scheme is the accuracy-first answer to the SAME traffic lever, at ¼ the bytes (INT8) vs f16's ½. The T3 cell must beat or explicitly merge with this lane; the f16 lane's sequence-forking diagnostic becomes the new lane's named bar.
3. **katgpt-rs Research 538 (arXiv:2609.04098) + the shipped Issue-879 harness** — explains why the GDN *modules* survive weight quant and derives the state-error plateau; its certification diagnostic SHIPS in this repo as `tests/issue879_gdn_quant_certification.rs` (plateau arm, `max/plateau ≤ 1.2`; impulse arm). It ships **no method to quantize the state itself** — and LeapQuant Fig. 3 is that same instrument turned around to measure a *method* instead of certifying *survival*. The two bracket the problem: 538/879 = why error stays bounded + the measuring stick; LeapQuant = when/where to inject it so it stays small.
4. **riir-infer Research 023 (FlashStates) + Issue 1201** — the serving lane that owns state checkpoints. *Signal diff:* 023 optimizes **how many** states are kept and **where** they're captured; LeapQuant optimizes **how big** each state is. Direct fusion (below).
5. **katgpt-rs Research 020 TurboQuant + Plan 043** — our closest quant codec lane is KV-scoped; TurboQuant is also the paper's strongest adapted baseline (8-bit 73.2 / 6-bit 60.1 — loses to LeapQuant everywhere). Confirms the internal lane targeted the other cache.
6. **Research 004 DQ / 009 LittleBit / 467 RRQ** — all weight-side. No state-quant coverage.

### Fusion (the two consumers that make this actionable)

- **Fusion A — serving checkpoints (Issue 1201, live).** 742 T4 + the 1201 T2 radix manager hold whole f32 GDN states per session; the paper's Fig. 1(b) + §4.3 numbers are exactly this surface: 3.4× smaller checkpoints → 41–56% memory cut → 1.4× more concurrent sessions. Quantized boundary states slot into 1201's T3 measured cells as a memory arm — it rides the existing pre-registered cell (plan 630), never a second benchmark lane.
- **Fusion B — the decode league arm.** Decode is the league's losing axis (m5ultra re-cell 0.888×/0.863×/0.842×, Bench 1161; 4090 tg128 ~0.970×); the state read+write is per-token bandwidth both boxes pay. An 8-bit state arm is a *named* decode lever beside `ffn_gate_up` (28.1%) — and the lane's named structural successor was ALREADY state precision: Issue 984 named bf16/f16 recurrent state ("halves the dominant state R+W traffic") and Bench 954 measured it (+0.44%, resident 144→72 MiB, promotion declined on sequence forking — cousin #2 above). LeapQuant-INT8 is the accuracy-first retake of that lever at ¼ the bytes. Honest caveats: (i) our league runs batch-1 — the paper's decode gains grow with batch, so the batch-1 share is **unmeasured on our shapes** (that measurement is the lane's T0, not a claim); (ii) Metal has no paper numbers — the bandwidth argument transfers, the magnitude does not; (iii) opponent lane status (llama.cpp GDN state quant) is **unverified** — any league claim is scoped to our A/B, never "first".
- **Fusion C — the G1 harness already exists.** The Issue-879 certification harness (`tests/issue879_gdn_quant_certification.rs`, Bench 871 record) gives the lane its accuracy gate before any kernel work — T1 adds windowed-INT8 arms to it rather than building a new diagnostic — and the Bench-954 sequence-forking read becomes the named deployment-length bar (the f16 lane died there; this lane must not). Argmax-flip census on the golden corpus rides the league's lossy-arm pin discipline (the 1176 posture precedent).

## 3. Verdict

**Gain** — ships (Apache-2.0, open-sourced 2026-11, reproducible bench tables), actionable (no windowed / sub-16-bit state lane exists anywhere in the stack — the incumbent state-precision posture is the opt-in per-step f16 arm whose promotion was already declined on accuracy; two live fusion consumers: Issue 1201 serving checkpoints + the decode campaign), and the mechanism is fully modelless (training-free, no calibration data — Path 0: every component is runtime-computable math, no training deferral in any direction). Not GOAT+ as a *claim*: the novelty is the paper's; our tier is adoption/adaptation of published SOTA on a lane we own — the same honest posture Research 023 took. The lane's own GOAT question (does it win on OUR boxes at OUR shapes) is Issue 1207 T3's pre-registered cell.

**Track separation:** single-track paper (inference serving). No training recipe content exists to file — the three-track adversarial panel is not triggered (nothing routes toward riir-train; the panel is mandatory only when classification touches training).

**MOAT gate (riir-infer, public substrate):** strengthens the moat — extends the hybrid-serving story from the KV half (919) to the state half, on the model families the league already serves, with the guard (drift_guard) and cache (1201) surfaces already in place to host it. Decision serving (reflex) and game runtime (riir-ai) untouched.

**Files:** this note + `riir-infer/.issues/1207` (work items + pre-registered proof path). No plan yet — the plan opens when T0's premise measurement lands and T3's bars freeze, per the 1201/630 precedent.
