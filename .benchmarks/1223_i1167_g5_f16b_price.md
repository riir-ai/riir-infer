## The arms

- **baseline** — the serving kernel verbatim: B-side activations f32 (4 bytes/element), matmul2d over float B + half A-staging.
- **f16b** — the SAME kernel with the input pointer + downcast site patched (`PATCH_F16_BODY`): `tensor<half>` B. Both matmul operands half; accumulator float. Drift-guarded patch (the first find-string had one space wrong — the assertion refused the run loudly, exactly as designed, before any timing row).

**Cast tax** (timed separately, subtracted in the NET): one `cast_f32_f16` elementwise pass over the same input per launch (0.150–0.191 ms across shapes) — the in-situ cost of producing the f16 copy; a producer-writes-f16 serving shape is the tax-free upper bound, named here, never assumed.

## Verdict: OVER — the f16-B rung graduates to the decider

The price-gate rule (≥1.5% e2e, sign-consistent): the NET projection reads ~65% per-launch class across the FFN+GDN+attn census shapes — two orders over the bar, every Δ-range disjoint. Graduate:

1. **Numerics decider (pre-registered):** per-family retention at the shipped posture (relaxed selector + the strict arm), one frozen read, the lossy-surface rule's per-family conditional retention gate — NOT bit-identity, which is unreachable by construction (the input rounds).
2. **Serving twin:** `MetalTensorGemm` gains the f16-B input variant + the input path (producer-writes-f16 preferred — the cast tax then never lands on the frame; the per-launch cast fallback bounds the worst case at −Δ). G3 decode-path regression check rides the feature flag.
3. **Paired Bench-937 frame-census A/B** on the twin (the rung C decider machinery, `TWIN_RELAXED` both arms), then the GOAT gate + feature-flag promotion per the discipline.

## Honest caveats (carried, not buried)

- The twin is an INSTRUMENT patch, not the serving path: the decider must re-prove engagement in situ (the Issue-1124 T1.5 lesson — prove the arm is reached in the measured posture).
- `gdn_ab` (16×5120, the GDN a/b projections) is launch-overhead-shaped (42% win but only 0.089 ms NET) — its weight (96/chunk × 8) amplifies small absolute ms; the NET projection carries it honestly through the guard.
- P=4096/32768 rows are NOT measured here (P=512 only): the B term scales with P·K while the A-dequant does not, so the B-bandwidth share GROWS with P — pp4096/pp32k are expected to be at least as favorable, measured at the decider, not assumed (the projection's frame reference is the Bench-937 posture; cross-posture extrapolation is a decider row, not this cell's).
- The `1355.96% e2e` projection number is arithmetically real (per-launch NET × 1024 launches) but reads absurd against a 500.86 ms frame because the frame itself would shrink — the verdict that matters is per-launch NET ≈ 2/3 of the GEMM wall, sign-consistent everywhere; the record reads the per-launch rows first, the projection second (the issue-1224 guard's own ordering).
