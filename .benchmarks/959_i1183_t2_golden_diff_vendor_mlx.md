## The two bugs the golden diff caught (the piecewise discipline paying for itself)

1. **`serial_walk_core` scored the SENDER's base, not the CANDIDATE's.** Both vendor references (SGLang Triton `_serial_table` — `s = base[None, :] + rms·s`, and MLX `RefinementTail.greedy` — `score = base[:, None, :] + …`) broadcast the candidate lane's base over the sender axis; our oracle wrote `base[j]` (sender-indexed), which makes base a per-row constant the argmax over candidates cannot see — wrong idx semantics AND wrong confidence masses. Fixed (`base[jp]`), regression test added (`serial_walk_core_scores_the_candidate_base`: TG≡0 ⇒ the winner is pure argmax over candidate bases).
2. **`build_serial_tables` read `write_w` TRANSPOSED for the TG half.** The vendor matmul is `[V,H] @ [H,R]` — `TG[v,o] = Σ_h u[h]·write_w[h·R+o]`; ours indexed `wb[o·H+i]`, scrambling rows into values beyond the ±H bound (impossible for the true contract — the fixture tell was `tg` entries of −650 where |TG| ≤ 512). The production drafter path (`serial_tail` → the same builder on the real checkpoint tensors) was affected too. Fixed (`wb[i·r+o]`), fold order unchanged (ascending h).

**The shape walk's numbers moved with the fix** (real checkpoint, blake3 `53d18516…` verified at load): chain `233648/25157/149688` → **`201633/143447/149688`**, conf `1.000/1.000/1.000` → **`1.000/0.891/1.000`** — the confidences are no longer degenerate on the real head either. The pre-fix T2 record's chain numbers were self-consistent garbage (no ground truth had ever seen them); this bench is the correction of record.

## The green-zero the diff also caught (fixture degeneracy)

The first fixture generation was numerically DEAD: at natural synthetic magnitudes the message half's heavy tails drive score gaps ~1e6× the confidence scale, the mass underflows to exactly 1.0 everywhere (`probs` all-1.0, `confs` all-1.0), and one scrambled TG row won every argmax — the two score formulas produce byte-identical outputs on it. A golden diff on that fixture passes trivially while proving nothing. Rescaled (probe-tuned via an LCG-replicating numpy mirror of the generator, `/tmp/dspine_scale_probe.py`): **pv_w ×2e-7** (bf16 re-rounded — inputs stay bf16-valued; the vendor build rounds pv_w to bf16 before its matmul, so both sides must see the same values) puts `rms·s` at ~0.4× base scale so the candidate base is visible to the argmax while the message half still perturbs winners; **stash rms ×30** (fp32 stash scalar on the vendor path — no bf16 store) keeps the mass live (top-2 gaps 6.2–25.4 vs scale ~17). The generator now carries a **degeneracy guard** (refuses to write a fixture whose `distinct_idx < 4` or whose probs collapse outside [0.05, 0.995]) — the green-zero cannot be regenerated silently.
