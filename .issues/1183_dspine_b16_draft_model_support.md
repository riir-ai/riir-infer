## What DSpine is (three sources, this filing's ground truth)

- **Paper**: [arXiv:2609.36173](https://arxiv.org/abs/2609.36173), "Draft in Parallel, Condition Through Depth: Adjacent Causal Injection for Speculative Decoding" (Zhang et al., SJTU + Tencent YouTu + XMU, 2026-09-28, CC-BY-4.0). Parallel speculative drafting where the causal conditioning chain unfolds over **network depth** instead of over the block: at every layer, gated **adjacent injection** writes each predecessor's predicted feature into its successor (immediate predecessor only), while all positions update in parallel.
- **The five pieces** ([project page](https://dspine-project.github.io/)): (a) **unified transfer space** — predictions travel in a fixed space built from the **target LM head's output embeddings**; an undecided predecessor sends its predicted feature, a decoded token enters as its embedding — one pathway carries either; (b) **adjacent causal injection** — a gated message (gate/message/write-back) from the immediate predecessor after EVERY layer; (c) **predecessor-conditioned decoding** — once a predecessor's token is decoded, its embedding replaces the predicted feature and the **last write is redone**, no new module; (d) **transition cache** — all K×K candidate pairs scored in one parallel pass, selection becomes a lookup (their post-backbone decode: DSpine 0.36 ms vs DSpark 0.88 ms per round, Qwen3-8B/SGLang); (e) **layer-wise output-embedding supervision** — TRAINING-time only; a loader consumes none of it.
- **Checkpoint** ([HF card](https://huggingface.co/tencent/Qwen3.8-27B-DSpine-b16), 2026-11-07): 5-layer draft model for Qwen3.8-27B, **block size 16** (the `b16` — the name is the BLOCK size, not the dtype), **8,192-token sliding window**, bf16 weights, ~2B params, Apache-2.0. The target supplies tokenizer + embeddings + LM head. Served through SGLang 0.5.22 with **dynamic verification referencing DSpark** and **ReplaySSM** (`--enable-linear-replayssm-spec --linear-attn-backend triton --mamba-ssm-dtype float32 --mamba-radix-cache-strategy extra_buffer --max-mamba-cache-size 64`) — the 27B pair rides the hybrid linear-attention target, so the draft carries linear-attention/SSM layers whose state replays at verification.
- **Repo**: [github.com/tencent/dspine](https://github.com/tencent/dspine) — inference code + `tencent/Qwen3-8B-DSpine-b16` released 2026-10; the README's supported-models table still lists Qwen3.8-27B as **"Coming soon"** — the README predates the 27B checkpoint drop; the HF card's 27B recipe is the fresher source (T0 reconciles any config drift between the 8B reference the code documents and the 27B checkpoint).
- **Upstream numbers (cross-fixture — never printed as our measurement**, the 1179 verdict-round-1 discipline): 8B family, same-budget retrains, T=0 7-benchmark mean acceptance — DSpine **7.83** > DFlash2 7.55 > DSpark 7.44 > Domino 7.05 > DFlash 5.92; 27B card acceptance lengths (greedy) 4.48–7.20 vs official DFlash2(block 8) 4.11–5.69; serving +23.3% over DFlash / +11.1% over DFlash2 (8B), ≤4.0× over AR; injection ≤0.15 ms/round.

## What is genuinely NEW (never faked as "same")

1. **Gated adjacent injection at every layer** — a depth-causal dependency chain. DFlash2 is block-local NON-causal attention + conv + selector (its config carries `is_causal:false`; the causal reading was implemented + REFUTED in riir-ai Issue 989). DSpine's block-attention causal posture + the gate/message/write-back algebra must be read at a pinned commit (T0) — the project page says "block-causal attention".
2. **The unified transfer space over TARGET output embeddings** — projections to/from the target LM-head embedding space at every layer boundary; wires the target's embedding table into the draft forward.
3. **Predecessor-conditioned decoding + the transition cache** — K×K pair scoring in one pass (K=16 → 256 pairs) + the last-write-redo; replaces DFlash2's selector entirely.
4. **ReplaySSM** — the draft carries linear-attention/SSM layers; verification replays SSM state (vendor pins f32 SSM dtype).
5. **k=16** — 2× DFlash2's block and past the GDN lane's `SPEC_MAX_K = 8` seam precedent; 1179 T2's k-invariance pre-check applies at k=16.

## The b16/bf16 loading posture (owner's blueprint, mapped)

- **Storage-not-math**: load bf16 as RAW `u16` bytes (`bytemuck::cast_slice` — bytemuck is already a dep; `half` is already an optional dep via `cubecl_runtime`/`ane_prefill`), dequant to f32 at kernel time — never scalar-emulate bf16 arithmetic on CPU. The `qwen38_dflash2_gpu.rs` posture: stream tensor-by-tensor, host peak = one tensor (~4 GB est. weights → fine on 96 GB boxes).
- Metal/wgpu: f32 math in shaders; bf16 bits ride as u16 storage (the `m32_kvf16` KV lane is the f16-storage precedent; bf16→f32 dequant is exponent-byte widen — no `half` in kernel code).
- **Determinism law (katgpt-rs Issue 940)**: draft logits feed argmax/rejection sampling — every reduction crossing an accept decision pins its fold order, same as the 1179 G1 reference discipline.
- Weights never committed (A1/A8): blake3 pin recorded HERE at T1; the pin rides every quoted cell.

**The forward (dspine_mlx/model.py + bridge.py — the op-for-op reference):**
1. **Context fusion**: draft input = target embed(block_ids); per-layer context = `hidden_norm(fc(target_hidden))` where target_hidden = the CONCAT of the 5 tapped target layers' hidden states [B, S, 25600]; context K/V are k-normed + RoPE'd and live in per-layer KV caches (SW-8192 trimming), refreshed after prefill/verify (`append_context`); block K/V are transient; block attention is CAUSAL over the 16 rows with every context row visible (SDPA `mask="causal"` over [ctx | block]).
2. **Bridge write after EVERY layer** (`DSpineCodeBridge.__call__`): raw = hidden+residual (bf16) → rms [fp32] → normalized → project via per-layer read weight (early_read_weights[0..3] for layers 0..3, read_weight for layer 4) → **code**: anchor row (row 0 of each block) takes `sqrt(1024)·codebook[anchor_token]`; rows 1..15 take `sqrt(1024)·projected/‖projected‖` (L2-normalized projections, NOT codebook entries — the codes are continuous) → **packed = codes @ packed_weightᵀ** where packed_weight = rows [gate.weight; predecessor_gate.weight; prev.weight] [1024, 3×512] → q/s/v = the three 512 halves → **gate = sigmoid(q + s_prev + b)** (s_prev = predecessor row's sender half; row 0 gated to ZERO — `where(row % T == 0, 0, gate·v_prev)`) → **delta = message @ feature_write_weights[layer]ᵀ** → **out = raw + rms·delta·(non-anchor & valid)** (the rms RESCALES the delta — the write is in rms units) → next layer input = RMSNorm(out) (fused; the layer's own input_layernorm is SKIPPED via input_normed). Last layer: the final norm is the model norm, applied by the write itself; `stash` keeps {raw, rms, packed[:, :512]} of the LAST write for the refinement tail.
3. **Refinement tail** (`propose.py::RefinementTail.greedy` — the exact_sender serial_table at bf16/f32 mix): candidates = top-16 of `rows @ lm_headᵀ` (two-stage chunked stable top-k, chunk 64, ties → lower id, ASCENDING ids); for each proposal row n and each candidate lane j: **base[n,j] = Σ_h (raw[n]·norm_w) · lm_head[cand[n,j]]**; **sender table** TSV[v] = [G_p; A] @ (sqrt(C)·codebook[v]) built OFFLINE over the vocab ([V,1024] bf16 tables, `build_serial_tables`: TG[v] = (lm_head[v]·norm_w) @ W_last, TSV[v] = [G_p;A] @ (sqrt(C)·codebook[v])) → m[n,j] = sigmoid(q[n] + TSV[sid,j,:512] + gate_b) · TSV[sid,j,512:] with **sid[n,j] = cand[n-1,j] (row n-1's candidates), row 0's sid = the ANCHOR token** → score[n,j,j'] = base[n,j'] + rms[n] · m·TG[cand[n,j']]ᵀ — the CANDIDATE lane's base (both references broadcast `base[None,:]` over the sender axis; CORRECTED 2026-11-09, bench 959 — the original note here wrote base[n,j], which the T2 oracle implemented and the golden diff caught) → **idx[n,j] = argmax_j'** (first-index ties) → the greedy CHAIN walk (`_serial_chain`): j₀ = idx[0, 0]… wait, the chain starts at lane 0 of row 0 and walks `idx` row by row, each row reading the PREVIOUS row's chosen lane. This is the "predecessor-conditioned decoding": each row's chosen candidate becomes the next row's sender conditioning, one table lookup per row.
