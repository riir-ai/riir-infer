|---|---|---|---|

| CPU ONNX 1 thread | 30.49× | 22.69 | P1.2 |
| CPU ONNX 4 threads | 49.23× | 22.69 | P1.2 |
| ANE fp16 pipe | 28.1–28.6× | **10.75** | P2.5 |
| ANE fp16 pipe (tvspeech) | **31.84×** (all-ANE n=100, quiet AC load=1.26, `p633_p23_cells.jsonl`) | **19.53** (+7.19 vs ref — G1 FAIL; but BETTER than the CPU ONNX lane it replaces: 20.82 fp / 21.79 int8 → −1.29 / −2.26) | P2.5 tv leg DONE 2026-11-19 (post-i1219 fix, plan 633 P2.5 row) |

  - **"CPU at 1 thread already beats the ANE pipe" is true on RTFx ONLY.** On fleurs the ANE pipe is ~**12 points BETTER on CER than the CPU ONNX lane** it would replace (10.75 vs 22.69) — the +1.46 G1 FAIL is measured against the NeMo REFERENCE (9.29), a different comparator. The two facts must never be pooled into one verdict.
  - The cheapest "CPU too hot" demote is still the thread step-down (no wedge exposure, no residency cost), and it is quality-neutral (22.69 at 1T = 22.69 at 4T). Whether the ANE rung is *better or worse* than the rung below it on quality is PER-FAMILY, now MEASURED on both: fleurs better (10.75 vs 22.69 ONNX); tvspeech better (19.53 vs 20.82 ONNX-fp — the n=3 smoke's +17.03 vs ref was a small-n artifact; the n=100 read is +7.19 vs ref, −1.29 vs the ONNX lane).

- **Adaptive activation when CPU too hot** = a thermal/contention governor over that ladder: sigmoid gate over box signals, hysteresis bands, per-clip demote with counted lines — the drift_guard shape (issue 1182: sigmoid threshold, per-shape-bucket runtime demote, fail-closed, one counted fallback line, env PROMOTE-ONLY, unarmed byte-identical). - **Cached may help** = warm residency. What a cache CAN buy: (a) switch cost — converted packages staged + `MLComputePlan` compiled (riir-infer-ane's existing compile cache), so activation is a plan load, not a conversion; (b) **switch boundary**: the streaming encoder cache differs between the fp16 ANE and fp32 CPU postures, so the governor may switch only at CLIP or UTTERANCE boundaries, never mid-stream (T3/T4 carry this). What a cache CANNOT buy: output caching — streaming ASR never sees repeated audio. Honest scope.

## The proof (cap arithmetic — every number from bench 1220, fleurs n=100 quiet, PROVENANCE lines quoted there)

1. **The speed case is CLOSED NEGATIVE at the current posture:** ANE fp16 pipe RTFx 28.1–28.6× vs CPU SIMD 49.2× → G2 ratio 0.57×; the owner's 6× bar ≈ 295× RTFx. The ANE cannot be sold on ASR speed at this tier; what it CAN carry is the quality column above.
2. **Overlap/async ceiling — CORPUS-LEVEL, and loose:** the decode tail is **22–23% of wall on the corpus rows** (1 − 28.09/36.61; the bench's "21%" slightly understates it; the real 13.08 s clip alone reads 26% — 90.7/(257.1+90.7) — that clip is NOT the corpus mix; its encoder-only RTFx is 50.9×, above the CPU corpus average, so T5's denominator must be SAME-CLIP CPU, never the corpus average). Perfect intra-stream pipelining (dispatch chunk N+1's encoder under chunk N's decode) caps the pipeline at encoder-only **36.6× = 0.74× of the CPU 4-thread lane — still a G2 FAIL**. **Preregistered expected value is lower:** the tail's 201 joint calls run on the ANE too and likely serialize with the next chunk's encoder; if only the CPU-LSTM third of the tail hides, the expected result is ≈ 30× ≈ **0.61× of CPU 4T** (≈ 0.98× of CPU 1T). The cell measures the real overlap fraction; it never promises the gate.
3. **The cap covers only INTRA-STREAM pipelining.** Running BOTH lanes concurrently on DISJOINT clips is additive throughput — not bounded by 0.74× — and is in fact the owner's actual "work together" question. It does not rescue G2 (per-lane speed is unchanged), but it is a distinct, honest arm (T2's concurrent arm).
4. **Per-call economics is the ANE's real gap:** the P0.2 roofline prices dispatch floor 0.11 ms vs compute 0.0022 ms at chunk shapes (~50×), and Posture B measured dispatch amortization (b112 = 1.8× b1 for 112× the frames; the FluidAudio working-set attribution REFUTED twice). The ANE is a throughput device; this workload is latency-bound (one encoder call per ~0.8 s audio, one joint call per token). Fewer/bigger calls — bigger chunk tiers, the p8 palettized arm — remain the SPEED levers of record (plan 633 P2.3/P2.5); this issue does not reprioritize them.
5. **Therefore the warm tier's value case is NOT raw speed. It is:**

## Governor shape (substrate-first answer — consume, never re-build)

- **Sensors:** bench_preflight / `box_state::capture()` (riir-reflex `src/harness/box_state.rs`) carries power source, power mode, load, swap, GPU util — **verified NO thermal/temperature axis exists** (source read 2026-11-15). The load axis alone can gate the CPU-4T → CPU-1T rung immediately.
- **Decision pattern:** drift_guard (issue 1182) — sigmoid threshold, per-posture runtime demote, fail-closed, ONE counted fallback line per demote, env PROMOTE-ONLY (opt-in arms on exact `1`; the DEFAULT flip is owner-gated on T0–T2 + the explicit per-family quality acceptance), unarmed = byte-identical incumbent.
- **Admission bar:** the splash distill's split-fit law (Batch 358): live fit T(s) = max(A, G + u·A) per device with the bandwidth-interference term, argmin ±1 unit at a **5% gain floor** — the ladder admits a rung on the FIT, never on a static "CPU hot ⇒ switch" rule; the lost-breaker law (trip retires the split AND forgets the remembered calibration) is the demote half. T2's total-system rows pass the same 5% floor.
- **Hysteresis:** band edges on the gate (the FSM law — a flapping governor oscillates the posture the same way a hard-edged hero oscillates states; the drive-surface armed-witness pattern pins the suite).
- **Scope law:** first consumer = the plan 633 ASR lane ONLY (riir-infer-ane + the p633 harness). No generic "compute tier governor" engine before a second consumer (the seam law; the seal-render limelight rings are the render-side cousin, different repo, not shared code).
