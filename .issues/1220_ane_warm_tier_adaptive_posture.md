## The directive, restated in lane vocabulary

- **ANE = warm executor, the LAST rung of a posture ladder — never a lone warm tier.** The honest ladder is **CPU 4 threads → CPU 1 thread → ANE**, and it needs TWO columns — RTFx AND CER — because the rungs are not quality-equivalent:

| ANE fp16 pipe (tvspeech) | pending (smoke: 33.5× per `p633_p23_cells.jsonl`) | pending (smoke: 29.37 = +17.03 vs ref — smoke row, never a gate) | P2.5 tv leg queued |

  - **"CPU at 1 thread already beats the ANE pipe" is true on RTFx ONLY.** On fleurs the ANE pipe is ~**12 points BETTER on CER than the CPU ONNX lane** it would replace (10.75 vs 22.69) — the +1.46 G1 FAIL is measured against the NeMo REFERENCE (9.29), a different comparator. The two facts must never be pooled into one verdict.
  - The cheapest "CPU too hot" demote is still the thread step-down (no wedge exposure, no residency cost), and it is quality-neutral (22.69 at 1T = 22.69 at 4T). Whether the ANE rung is *better or worse* than the rung below it on quality is PER-FAMILY: fleurs recorded better; tvspeech unknown (n=100 leg pending; the n=3 smoke read +17.03 vs ref).
  - **OPEN QUESTION (T0 resolves): is the ONNX "piecewise dictation" CER (22.69) comparable to the other rows** — different export, decode recipe or normalization — or is the CPU lane genuinely a much lower-quality posture? The rung table's quality column is provisional until T0 answers this.
- **Adaptive activation when CPU too hot** = a thermal/contention governor over that ladder: sigmoid gate over box signals, hysteresis bands, per-clip demote with counted lines — the drift_guard shape (issue 1182: sigmoid threshold, per-shape-bucket runtime demote, fail-closed, one counted fallback line, env PROMOTE-ONLY, unarmed byte-identical). No magic thresholds (house law): activation = σ((signal − center)/scale) with band edges; the sprint!053 GREED lesson applies (weights past the sigmoid ceiling measure blind).
- **Cached may help** = warm residency. What a cache CAN buy: (a) switch cost — converted packages staged + `MLComputePlan` compiled (riir-infer-ane's existing compile cache), so activation is a plan load, not a conversion; (b) **switch boundary**: the streaming encoder cache differs between the fp16 ANE and fp32 CPU postures, so the governor may switch only at CLIP or UTTERANCE boundaries, never mid-stream (T3/T4 carry this). What a cache CANNOT buy: output caching — streaming ASR never sees repeated audio. Honest scope.

## The proof (cap arithmetic — every number from bench 1220, fleurs n=100 quiet, PROVENANCE lines quoted there)

1. **The speed case is CLOSED NEGATIVE at the current posture:** ANE fp16 pipe RTFx 28.1–28.6× vs CPU SIMD 49.2× → G2 ratio 0.57×; the owner's 6× bar ≈ 295× RTFx. And the sharper floor: **CPU at 1 thread (30.49×) already beats the ANE pipe (28.1×) on RTFx** while spending CPU on mel + LSTM island + host plumbing. The ANE cannot be sold on ASR speed at this tier; what it CAN carry is the quality column above.
2. **Overlap/async ceiling — CORPUS-LEVEL, and loose:** the decode tail is **22–23% of wall on the corpus rows** (1 − 28.09/36.61; the bench's "21%" slightly understates it; the real 13.08 s clip alone reads 26% — 90.7/(257.1+90.7) — that clip is NOT the corpus mix; its encoder-only RTFx is 50.9×, above the CPU corpus average, so T5's denominator must be SAME-CLIP CPU, never the corpus average). Perfect intra-stream pipelining (dispatch chunk N+1's encoder under chunk N's decode) caps the pipeline at encoder-only **36.6× = 0.74× of the CPU 4-thread lane — still a G2 FAIL**. **Preregistered expected value is lower:** the tail's 201 joint calls run on the ANE too and likely serialize with the next chunk's encoder; if only the CPU-LSTM third of the tail hides, the expected result is ≈ 30× ≈ **0.61× of CPU 4T** (≈ 0.98× of CPU 1T). The cell measures the real overlap fraction; it never promises the gate.
3. **The cap covers only INTRA-STREAM pipelining.** Running BOTH lanes concurrently on DISJOINT clips is additive throughput — not bounded by 0.74× — and is in fact the owner's actual "work together" question. It does not rescue G2 (per-lane speed is unchanged), but it is a distinct, honest arm (T2's concurrent arm).
4. **Per-call economics is the ANE's real gap:** the P0.2 roofline prices dispatch floor 0.11 ms vs compute 0.0022 ms at chunk shapes (~50×), and Posture B measured dispatch amortization (b112 = 1.8× b1 for 112× the frames; the FluidAudio working-set attribution REFUTED twice). The ANE is a throughput device; this workload is latency-bound (one encoder call per ~0.8 s audio, one joint call per token). Fewer/bigger calls — bigger chunk tiers, the p8 palettized arm — remain the SPEED levers of record (plan 633 P2.3/P2.5); this issue does not reprioritize them.
5. **Therefore the warm tier's value case is NOT raw speed. It is:**
   - **V1 — CPU headroom release under contention** — gated by **T0 first**: CPU-seconds per audio-second for the ANE posture vs CPU at 1 thread. The existing harness rows may not carry rusage — if not, T0 is a SHORT RE-RUN of the same cells with rusage recorded; CPU-seconds is load-tolerant, so it still needs no exclusive window. **Kill read:** if the ANE posture does not use materially less CPU than the 1-thread lane, **V1 is dead before any window is spent**.
   - **V2 — thermal/energy sustain** — T1 measures **joules per audio-second (idle-subtracted), not watts**: at 0.57× speed the ANE needs under 0.57× the active power of CPU-4T just to break even. T1 first shows the CPU lane THROTTLES AT ALL on an M5 Ultra under sustained load — if it does not, **V2 collapses to energy-only** (a cost argument, not a sustain argument). Include the CPU 1-thread arm in every T1 row.
   - **V3 — QUALITY IS PART OF THE VALUE CASE, PER FAMILY (the lossy-surface rule, corrected in round 2).** The rungs differ in quality: on fleurs the ANE rung is ~12 points BETTER than the CPU ONNX lane (10.75 vs 22.69); the +1.46 G1 FAIL is against the NeMo reference, not against the served incumbent. On tvspeech the ANE quality direction is UNKNOWN (n=100 pending; smoke +17.03 vs ref). So the governor's ladder moves a TRANSCRIPT-QUALITY dial, per family, in different directions — transcript quality must never depend silently on box temperature: the per-family delta is stated against BOTH the reference AND the served incumbent, never pooled, and per the lossy-surface promotion rule the quality trade is **accepted explicitly by the owner** before any activation posture ships — never silently.
   - **V4 — the wedge is a PRECONDITION.** i1219 (content-correlated ANE sync-call deadlock; direction 2 dead, direction call = 3: per-clip CPU/ONNX fallback with a killlist pre-screen as the detection half) means any activation must demote per-clip — exactly drift_guard's counted-demote shape. The governor inherits the pre-screen; no activation posture ships without it. Overlap (T5) means concurrent ANE requests on the deadlock path, so T5 is pre-screen-gated too.

## Governor shape (substrate-first answer — consume, never re-build)

- **Sensors:** bench_preflight / `box_state::capture()` (riir-reflex `src/harness/box_state.rs`) carries power source, power mode, load, swap, GPU util — **verified NO thermal/temperature axis exists** (source read 2026-11-15). A thermal signal is NEW substrate; the sudo-free Apple-Silicon-valid candidates are split by INSTRUMENT: thermal sensors for the throttle probe and the governor — **`pmset -g therm` and `ProcessInfo.thermalState` (thermalMonitoringEnabled)** — and the joule-meter family for T1 — IOReport-class energy readings or a `powermetrics` sudoers entry (`sysctl machdep.xcpm` dropped — Intel-only). The load axis alone can gate the CPU-4T → CPU-1T rung immediately.
- **Decision pattern:** drift_guard (issue 1182) — sigmoid threshold, per-posture runtime demote, fail-closed, ONE counted fallback line per demote, env PROMOTE-ONLY (opt-in arms on exact `1`; the DEFAULT flip is owner-gated on T0–T2 + the explicit per-family quality acceptance), unarmed = byte-identical incumbent.
- **Admission bar:** the splash distill's split-fit law (Batch 358): live fit T(s) = max(A, G + u·A) per device with the bandwidth-interference term, argmin ±1 unit at a **5% gain floor** — the ladder admits a rung on the FIT, never on a static "CPU hot ⇒ switch" rule; the lost-breaker law (trip retires the split AND forgets the remembered calibration) is the demote half. T2's total-system rows pass the same 5% floor.
- **Hysteresis:** band edges on the gate (the FSM law — a flapping governor oscillates the posture the same way a hard-edged hero oscillates states; the drive-surface armed-witness pattern pins the suite).
- **Scope law:** first consumer = the plan 633 ASR lane ONLY (riir-infer-ane + the p633 harness). No generic "compute tier governor" engine before a second consumer (the seam law; the seal-render limelight rings are the render-side cousin, different repo, not shared code).
